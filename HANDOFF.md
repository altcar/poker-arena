## How the competition teams were found

The competition's submission form is not available. The event rules say every
team **forked `Manchester-AI-Society/poker_bot`**, so the fork list is a much
more reliable map than a team-name search. The pipeline is:

1. `gh api repos/Manchester-AI-Society/poker_bot/forks?per_page=100` lists the
   forks.
2. The fork's pickle filename identifies the team (`apex_poker.pkl` →
   `apex_poker`; `bismillahInsurance.pkl` → `bismillahinsurance`; aliases for
   `SK_Poker`, `Zak`, `ask-chatgpt`, `myteam`).
3. Fork owner/repository names resolve the rest (`brinzeroseven`,
   `Markus-He`, `study-holic`, `devjoe9`, `humza000`).
4. For teams that did not fork, `gh search repos <team>` is tried, but a
   candidate is only accepted when it contains a `model.py` or `.pkl` and looks
   like a poker bot.
5. `required_files.py` reads the pickle's globals and copies only the pickle
   plus the `.py` files it imports.

Result: **57 of 68 teams have files** in `all-teams/`. The 11 that could not be
found publicly are listed in `data/team_files.csv` with `status=missing`.
`data/missing_candidates.json` records the search results.

Files:

- `data/team_files.csv` — one row per competition team: status, repo,
  `model.py`, pickle, all pickles, all files.
- `data/team_repos_resolved.json` — verified repo for every found team.
- `data/team_repos_extra.json` — manual additions (5 teams whose folders were
  already present, plus `ddd`).
- `src/teams_data.js` — team rows with the verified `github_repo`; the Teams
  page links each team to that repo.

## Architecture

- `src/` — the JavaScript engine (a line-for-line port of the Python
  `engine.py`, `game_state.py`, `card_utils.py`, `player_action.py`,
  `policy.py`, `botcore.py`), the five bots, the serialisable `Game`, and the
  Worker.
- `src/pyrandom.js` — Python's MT19937 + `random.sample`, so the JS Monte-Carlo
  draws match the Python model exactly.
- `src/worker.js` — the Worker: static assets + JSON API (`/api/session`,
  `/api/session/:id/action`, `/api/session/:id/next`, `/api/decision`,
  `/api/tournament`, `/api/teams`, `/api/teams.csv`, `/api/matches`).
- `src/our_tournament_data.js` — generated by `scripts/make_our_tournament.mjs`
  from `data/tournament_results.json`; served by `/api/tournament`.
- `public/` — the SPA (`index.html`, `app.js`, `style.css`, `data/`).
- `python/` — the original Python source (including `goldman-stanley.pkl` and
  the recovered `model_a.py` … `model_e.py`).
- `all-teams/` — each bot's `.pkl` and the `.py` files it imports.
- `scripts/` — fork sync, CSV, tournament and verification tools.
- `data/` — generated dumps (`team_files.csv`, `tournament_results.json`,
  `available_teams.json`, `all-teams.csv`, …).

## Front-end changes

- **Play:** if there is no session and no saved selection, the page asks you to
  pick opponents on Teams. If there is a saved selection, it asks “Ready to
  play?” and offers **Yes, start the game**, **Change models**, **No, just
  watch**. A **Start a new game** button is always visible once a table exists.
- **Seats:** seat 0 is at bottom centre; the other seats are spread around the
  oval with a gap at the bottom, so seat 0 never overlaps seat 1.
- **Teams:** a “Playable bots” table has checkboxes for the five JS bots and a
  floating **Continue (N selected)** button. The “All competition bots (68)”
  table links each team to the verified repo (or its detail page).
- **Head-to-head:** our round robin matrix and standings first; the official
  competition matrix and the five-bot matrix are collapsible.
- **Matches:** our matches with a team filter and a `our-tournament.json`
  download.

## Tournament

`scripts/run_tournament.py` was fixed so each of the five fork bots loads its
own module (`model_a`, `model`, `model_c`, …) instead of all loading `model`.
It supports sharding:

```sh
.venv/Scripts/python.exe scripts/run_tournament.py --deals 10 --shard 0/4
```

`scripts/merge_tournament.py` merges the shards, recomputes the standings and
the two-way matrix, and writes `data/tournament_results.json`.
`scripts/make_our_tournament.mjs` turns that into `src/our_tournament_data.js`.

The current run used **10 duplicate deals per pairing** for all 62 available
models (5 fork bots + 57 competition teams). `ddd` was added after the shards
started, so it was filled in with a `--focus ddd` run.

## Deployment

Two git-connected paths are set up:

1. **Cloudflare Workers Builds** — connected to `altcar/poker-arena` on `main`,
   deploy command `npx wrangler deploy`. Pushes auto-build and deploy.
2. **GitHub Actions** — `.github/workflows/deploy.yml`, needs the
   `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets.
